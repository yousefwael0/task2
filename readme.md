# Task 2 — Autonomous Research Agent
## Yousef Wael Muhammad Atta - 20231700264
## Overview

This project is the implementation of **Task 2** from the Agentic AI practical.

The objective of the task was to combine an autonomous LangGraph research agent with an interactive dashboard. The resulting system allows a user to enter a research objective, observe the agent's execution live, inspect its state, and receive a structured Markdown report.

The key requirement of the task is the agent's ability to **evaluate its own research, identify shortcomings, retry the research using the Critic's feedback, and eventually approve the result**.

The implemented system consists of:

- A LangGraph-based autonomous research agent
- A FastAPI backend exposing the agent
- A Streamlit dashboard
- Document upload and retrieval using LlamaIndex
- Groq-powered LLM inference
- Live execution streaming using Server-Sent Events (SSE)
- Token usage tracking
- Structured report generation and Markdown export

## Task Objective

The required workflow is:

```text
                    ┌──────────────┐
                    │    Planner   │
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │  Researcher  │
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │    Critic    │
                    └──────┬───────┘
                           │
                    Quality ≥ 0.8?
                       /         \
                     Yes          No
                      │            │
                      ▼            ▼
               ┌───────────┐  Retry limit?
               │ Reporting │      │
               └─────┬─────┘    No ──────► Planner
                     │
                     ▼
                 Final Report
````

The retry cycle is limited to a maximum of **2 retries** to prevent uncontrolled execution.

The system must not simply repeat the same plan during a retry. The Planner receives the Critic's feedback and uses it to produce a revised research plan.

---

## Implementation

### Agent Architecture

The agent is implemented using LangGraph and consists of the following nodes:

### Planner

Breaks the user's research objective into a set of concrete research tasks.

During a retry, the Planner also receives the previous Critic feedback so that the new plan addresses the identified gaps.

### Researcher

Executes the tasks generated by the Planner.

When documents are uploaded, the Researcher uses the document retrieval system to obtain relevant excerpts. When no documents are available, it falls back to the model's general knowledge.

### Critic

Evaluates the research findings against the original objective.

The Critic produces:

* A quality score between `0.0` and `1.0`
* Written feedback describing missing information or weaknesses

The quality threshold is:

```text
0.8
```

### Decision

The router determines whether the result should be approved or sent back to the Planner.

If the quality score is below the threshold and the retry limit has not been reached, the graph loops back to the Planner.

If the retry limit has been reached, the graph terminates gracefully and accepts the result rather than looping indefinitely.

### Reporting

The Reporting node generates the final structured report.

The output is validated using Pydantic before being converted into Markdown for download.

---

## Retry Logic

The retry mechanism is one of the main requirements of the task.

The configuration is:

```python
QUALITY_THRESHOLD = 0.8
MAX_RETRIES = 2
```

A typical execution is:

```text
Planner
  ↓
Researcher
  ↓
Critic → Score: 0.55
  ↓
Decision → Retry
  ↓
Planner receives Critic feedback
  ↓
Researcher
  ↓
Critic → Score: 0.86
  ↓
Decision → Approve
  ↓
Reporting
```

This demonstrates that the agent can identify a low-quality result and autonomously perform another research cycle.

## Live Reasoning Stream

The backend streams LangGraph execution events to the dashboard using **Server-Sent Events (SSE)**.

As each node executes, the frontend receives the corresponding event and updates the interface.

For example:

```text
Planner completed
    ↓
Researcher completed
    ↓
Critic completed — quality: 0.55
    ↓
Decision — retry
    ↓
Planner completed
    ↓
Researcher completed
    ↓
Critic completed — quality: 0.86
    ↓
Decision — approved
    ↓
Reporting completed
```

This makes the retry cycle visible during execution rather than displaying only a final result.

# Document Retrieval

The task requires uploaded documents to be accessible to the Researcher.

The implementation uses:

* **LlamaIndex** for document indexing and retrieval
* **HuggingFace Sentence Transformers** for embeddings
* `sentence-transformers/all-MiniLM-L6-v2` as the embedding model

Supported upload formats:

* PDF
* TXT
* Markdown

The documents are indexed and associated with the current session.

When the Researcher executes a task, relevant excerpts are retrieved and provided to the LLM as research context.

If no documents are uploaded, the system falls back to model knowledge and identifies those findings as unverified model knowledge.

# Backend

The task was implemented with a FastAPI backend to separate the agent from the dashboard.

```
┌─────────────────────────────────────────────────────┐
│                  Streamlit Frontend                 │
│                                                     │
│  Chat │ Controls │ File Upload │ State │ Export    │
└───────────────────────┬─────────────────────────────┘
                        │ HTTP / SSE
                        ▼
┌─────────────────────────────────────────────────────┐
│                   FastAPI Backend                   │
│                                                     │
│  /config │ /models │ /upload │ /run │ /health      │
└───────────────────────┬─────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│                 LangGraph Agent                    │
│                                                     │
│  Planner → Researcher → Critic → Decision           │
│                ↑                  │                 │
│                └──── Retry ───────┘                 │
│                                                     │
│                     ↓                               │
│                  Reporting                          │
└─────────────────────────────────────────────────────┘
                        │
             ┌──────────┴──────────┐
             ▼                     ▼
        Groq LLM             LlamaIndex
                              + HuggingFace
                              embeddings
```

This separation keeps the agent independent from Streamlit and provides a clean interface for running the agent remotely.

### Main API endpoints

| Endpoint       | Purpose                                      |
| -------------- | -------------------------------------------- |
| `GET /health`  | Backend health check                         |
| `GET /config`  | Retrieve runtime configuration               |
| `POST /config` | Configure the Groq API key                   |
| `GET /models`  | Retrieve available Groq models               |
| `POST /upload` | Upload and index documents                   |
| `POST /run`    | Execute the research agent and stream events |

# Guardrails

The implementation includes the required safeguards against uncontrolled agent execution.

### Explicit quality threshold

```python
QUALITY_THRESHOLD = 0.8
```

### Maximum retries

```python
MAX_RETRIES = 2
```

The graph cannot retry indefinitely.

If the maximum retry count is reached, the system finishes gracefully even if the final quality score remains below the threshold.

# Task Demonstration

The expected demonstration sequence is:

```text
1. Enter research objective
2. Planner generates research tasks
3. Researcher performs research
4. Critic evaluates the findings
5. Critic produces a score below 0.8
6. Decision routes back to Planner
7. Planner uses Critic feedback to revise the plan
8. Researcher performs the revised research
9. Critic evaluates the improved result
10. Quality score reaches the approval threshold
11. Reporting generates the final report
12. Markdown report is exported
```

The retry cycle is the central demonstration of the task because it shows the autonomous feedback loop implemented with LangGraph.
